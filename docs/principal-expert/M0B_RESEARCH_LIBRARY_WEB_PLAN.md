# M0-B ระยะ 6 — แผนคลังผลงานวิชาการบนเว็บไซต์คู่มือ

วันที่ 24 ต.ค. 2569 | สถานะ: แผนงาน ไม่ใช่ฟีเจอร์ที่เผยแพร่แล้ว

## เป้าหมาย
สร้างคลังอ้างอิงที่เปิดอ่านบนเว็บไซต์คู่มือได้ทั้งมือถือและแท็บเล็ต ค้นหาชื่อผลงาน ผู้เขียน ประเภท แหล่งเผยแพร่ และเปิดลิงก์ต้นฉบับได้ โดย **ไม่อ้างว่าเอกสารทั่วไปเป็นผลงานที่ผ่านวิทยฐานะ**

## โครงสร้างข้อมูล
ใช้ JSON ที่ตรวจสอบ schema ได้เป็น source of truth; Markdown เป็นคำอธิบายและคู่มือ ไม่คัดลอกข้อมูลซ้ำหลายแห่ง

แต่ละ record ต้องมี:
- id, title, authors[], document_type, verification_level, approval_evidence_url (nullable), approval_date (nullable)
- source_page_url, pdf_url (nullable), doi (nullable), publisher, publication_year
- link_checked_at, link_status (verified/unverified/broken), access_rights (public/permission_required/unknown), archived_copy_path (nullable)
- topics[], abstract_summary (nullable), notes, last_updated
- ไม่เก็บข้อมูลส่วนบุคคลของนักเรียนหรือเอกสารที่ไม่มีสิทธิ์เผยแพร่

**ระดับหลักฐาน:** A=ประกาศอนุมัติและไฟล์ฉบับเต็มตรงกัน; B=ประกาศอนุมัติและบทคัดย่อ/บางส่วน; C=ประกาศอนุมัติแต่ยังไม่พบไฟล์; D=บทความทั่วไปยังไม่ยืนยันว่าเป็นผลงานที่ผ่าน

## แผนดำเนินการ
1. P0: สร้าง schema และ seed JSON จากลิงก์ที่มีอยู่ โดยทุกลิงก์เริ่ม unverified จนตรวจเปิดจริง
2. P1: เพิ่มหน้า Library บนเว็บไซต์คู่มือ: ค้นหา/กรอง/เรียงลำดับ/ป้ายระดับหลักฐาน/เปิดแหล่งต้นฉบับ/รายงานลิงก์เสีย
3. P2: หน้ารายละเอียดแสดงชื่อเรื่อง ผู้แต่ง สรุป สถานะอนุมัติ วันที่ตรวจ และลิงก์ต้นฉบับ/PDF; รองรับบันทึกอ่านล่าสุดและรายการโปรดในเครื่อง (local-first)
4. P3: เพิ่มงานตรวจลิงก์ตามรอบและบันทึกผลแบบตรวจสอบย้อนกลับ; ไม่บังคับ GitHub Actions
5. P4: คัดเลือก PDF ที่อนุญาตให้จัดเก็บสำเนาเท่านั้น; บันทึก SHA-256 และเงื่อนไขลิขสิทธิ์ก่อนนำเข้า repo หรือพื้นที่จัดเก็บที่เหมาะสม
6. P5: เพิ่มมุมมองเทียบงานวิจัยกับ WD Growth Together พร้อมอ้างหน้า PDF หลังอ่านจริง

## ข้อกำหนด UX
- Mobile-first / tablet-first, สอดคล้อง e-book/PWA เดิม
- โหมดถนอมสายตา ปรับขนาดตัวอักษร และรองรับการเข้าถึง
- เปิดลิงก์ภายนอกโดยแสดงโดเมนต้นทาง ไม่ฝัง PDF บุคคลที่สามโดยไม่มีสิทธิ์
- สถานะลิงก์เสีย/ยังไม่ตรวจชัดเจน
- รองรับข้อมูลแบบ static JSON ก่อนพิจารณาฐานข้อมูล server-side
- ไม่เพิ่ม PIN กับผลงานสาธารณะโดยไม่จำเป็น; เอกสารภายในที่มีข้อมูลอ่อนไหวควรใช้การยืนยันตัวตนและสิทธิ์ฝั่งเซิร์ฟเวอร์ ไม่ใช่ PIN ที่ตรวจด้วย JavaScript อย่างเดียว

## Acceptance criteria
- ค้นด้วยชื่อผู้เขียน/คำในชื่อเรื่องและกรองประเภทได้
- ทุกผลมีลิงก์ต้นทางและระดับหลักฐาน
- ไม่มีลิงก์ที่แต่งขึ้นหรืออ้างว่า PDF ผ่านประเมินโดยไม่พิสูจน์
- ไม่กระทบหน้าอ่าน e-book เดิมและใช้งานบน iPhone/iPad
- มี fallback เมื่อ JSON โหลดไม่ได้หรือลิงก์ต้นทางเสีย
- ทดสอบ local ก่อนเผยแพร่จริง

## งาน M0-B เชิงวิจัยที่ยังค้าง
- อ่าน PDF ฉบับเต็มจริงและสกัดเลขหน้า
- ตรวจประกาศ ก.ค.ศ. รายบุคคล
- พัฒนาบทที่ 1–3 หลังยืนยันหลักฐานและแผนวิจัย
