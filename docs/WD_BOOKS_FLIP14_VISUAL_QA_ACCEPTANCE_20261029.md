## หลักฐานเพิ่ม — RT ป.1 โหมดมืด 160% (ผู้ใช้งานส่งภาพ 29 ต.ค. 2569)

ได้รับภาพหน้าจอ `SAR-INFO-02` ใน embedded Flipbook จากการทดสอบบน Desktop: โหมดมืด, ตัวอักษร **160%**, แสดง **หน้า 2–3 / 15**, สารบัญเลือกบท `2. RT ป.1 — แนวโน้มความสามารถด้านการอ่าน`.

**PASS เฉพาะหน้าที่มองเห็นในภาพ:**
- เนื้อหาและข้อความหัวข้อภาษาไทยครบ ไม่พบล้นขอบกระดาษหรือข้อความซ้อนกันในภาพ
- กราฟแสดง 3 รายการครบแม้ถูกแบ่งสองหน้าอย่างเหมาะสม: อ่านออกเสียง **93.16 → 78.71**, อ่านรู้เรื่อง **81.5 → 76**, รวมสองด้าน **87.33 → 77.35** (หน่วยร้อยละ)
- แสดงข้อความ Insight ว่า RT รวมสองด้านลดลง 9.98 คะแนน, อ่านออกเสียงลดลง 14.45 คะแนน, อ่านรู้เรื่องลดลง 5.50 คะแนน และบล็อกอ้างอิงต้นฉบับ
- การจัดหน้าแน่นแต่มีช่องว่างเหลือพอ; ในภาพไม่มีกราฟแถวใดถูกตัดครึ่ง; ปุ่มก่อนหน้า/ถัดไปและแถบควบคุมยังปรากฏ

**NOT TESTED:** การคลิกพลิกหน้าจริงต่อจากหน้า 2–3, การเปลี่ยนฟอนต์/หมุนหน้าจอขณะอ่าน, ความพอดีของทุกหน้า, รายการ NT และ O-NET, iPhone/iPad, PWA/เสียง/ออฟไลน์, และการจัดหน้าที่ 90%/100% ในพื้นที่เดียวกัน. แม้ RT ผ่านภาพ 160% หน้านี้ ก็ห้ามยกระดับทั้งเล่มเป็น PASS.

**สถานะภาพหน้าจอในแชท:** หลักฐานอยู่ในการสนทนา ไม่ได้ Commit รูปภาพส่วนตัวเข้าระบบ GitHub.

**UX observation:** ในสองภาพพบตัวเลือกสารบัญยังบอกชื่อ *บทของกระดาษซ้าย* แต่กระดาษขวาเริ่มบทใหม่แล้ว (RT→NT, NT→O-NET) ทำให้ผู้ใช้เข้าใจผิดว่าอยู่ในบทก่อนหน้าได้ สอดคล้องโค้ด `renderStatus()` ซึ่งใช้ `visibleSourceIndex()`/ `cornerModel.firstReadable(...)` แล้วตั้ง `chapterSelect.value` ตามหน้าแรกใน spread. ควรเพิ่มเกณฑ์ตรวจสถานะบทใน spread สองบทโดยไม่เปลี่ยนการติดตาม Progress หรือการกลับ Reader ก่อนวางแผนแก้ UI

**Pagination observation:** ทั้งสองภาพมีพื้นที่หน้ากระดาษว่างหลังเนื้อหาจบบทอยู่มาก ซึ่งสอดคล้องกับ `paginate()` เรียก `freshPage(section)` เมื่อเริ่มทุกบท; อาจเป็น intentional chapter break แต่ยังไม่ตัดสินว่าเป็น defect หรือควรบังคับให้บทใหม่เริ่มหน้าขวาเท่านั้นโดยไม่ตรวจเนื้อหาครบเล่ม. ไม่ควรแก้ด้วยวิธีย้าย/ทิ้งข้อความหรือรวมบทโดยไม่มีแผนทดสอบ

**Clarification by user:** กราฟ NT และ O-NET **ยังอยู่หน้าถัดไป** หลังหน้าที่เปิดต้นบทในภาพ จึงไม่ใช่กรณีกราฟหายหรือการแสดงผลล้มเหลว ภาพหน้าที่ให้มามีเนื้อหาเปิดบทก่อน แล้วกราฟเลื่อนไปหน้าถัดไปตามการแบ่งเนื้อหาเมื่อใช้ตัวอักษร 160% สถานะเนื้อหากราฟ = **ผู้ใช้ยืนยันว่ามีอยู่หน้าถัดไป**; ส่วนการตรวจค่ากราฟและความพอดีของแต่ละแถวบนหน้านั้นยัง **NOT TESTED**. หากจะปิด visual gate ต้องตรวจหน้าที่มีกราฟจริง โดยไม่จำเป็นต้องเปลี่ยนวิธีแบ่งหน้าเพียงเพราะภาพแรกยังไม่เห็นกราฟ. แยกประเด็นสารบัญเลือกบทตามกระดาษซ้ายเป็น UX review ต่างหาก.

**Still NOT TESTED:** ทั้งหมดของ NT/O-NET chart values ณ 160%, motion/flip gestures, desktop page-fit ครบทุกหน้า, iPad/iPhone/PWA, audio/offline; ไม่เปลี่ยน Production

## D. หลักฐานและเกณฑ์รับงาน

บันทึกสำหรับแต่ละ FAIL: `อุปกรณ์ + OS/Browser + ขนาดจอ + ชื่อหนังสือ + เลขหน้า/บท + ขั้นตอนที่กด + ภาพ/วิดีโอ`. ให้ใช้สถานะ PASS / FAIL / NOT TESTED เท่านั้น

**ยังไม่อนุมัติ Merge/Deploy:** ต้องผ่านภาพ SAR และข้อมูลทุกเล่มหลัก, ไม่พบ clipping, Reader fallback, device/mobile gestures และไม่มีปัญหาเสียง/PWA ที่ตรวจได้ในสภาพจริง จากนั้นจึงวาง Release แยก (เลขเวอร์ชันใหม่ ไม่ใช่ 1.3.68) พร้อมแผน Rollback โดยไม่ลบ `wd-manual-reader-v2`.
