# AI & School Today — Master Plan M0

เวอร์ชัน: Draft 0.1 | วันที่: 25 ตุลาคม 2569
สถานะ: **Planning only / Not approved for publication**

## 1. วัตถุประสงค์
พัฒนาครูให้สามารถ (1) กำหนดข้อตกลงใช้ AI ตามวัย (2) ออกแบบงานที่เด็กแสดงวิธีคิด (3) ตรวจสอบคำตอบ AI และหลักฐาน (4) ประเมินความก้าวหน้าจริง และ (5) สะท้อนผลผ่าน PLC

## 2. กลุ่มเป้าหมายและข้อจำกัด
ครูปฐมวัยและประถมศึกษา รวมถึงผู้บริหาร/วิทยากร; ปฐมวัยและประถมต้นเน้น **ครูใช้ AI เตรียมการสอน** ไม่กำหนดให้เด็กสมัครบัญชีหรือใช้บริการ AI เอง ต้องตรวจข้อกำหนดอายุ ความยินยอม นโยบายข้อมูล และความเหมาะสมรายเครื่องมือก่อนใช้

## 3. โครงสร้าง 8 บท
| บท | หัวข้อ | ชิ้นงานครู |
|---|---|---|
| 1 | AI กับการเปลี่ยนแปลงห้องเรียน | แผนผังบทบาทครู-เด็ก-AI |
| 2 | จริยธรรมและข้อตกลงการใช้ AI | Classroom agreement |
| 3 | งานที่ AI ช่วยแต่เด็กคิดเอง | ใบงานก่อน/หลังปรับ |
| 4 | จากตรวจคำตอบสู่ดูวิธีคิด | ชุดคำถาม probing |
| 5 | AI & Data Literacy | กิจกรรมตรวจข้อเท็จจริง |
| 6 | การประเมินยุค AI | รูบริกและหลักฐาน |
| 7 | ตัวอย่างตามวัยและวิชา | แผนกิจกรรม |
| 8 | PLC และการพัฒนาต่อเนื่อง | วงจรทดลอง-สะท้อน-ปรับ |

แต่ละบทต้องมี: วัตถุประสงค์, ความรู้พื้นฐาน, กรณีตัวอย่าง, กิจกรรมครู, ชิ้นงาน, วิธีตรวจรับ, ความเสี่ยงและข้อควรระวัง

## 4. หลักการออกแบบการเรียนรู้
- กำหนดระดับการใช้ AI ให้ชัด: ไม่ใช้ / ใช้ค้นแนวคิด / ใช้รับข้อเสนอแนะ / ใช้สร้างร่างโดยต้องเปิดเผย
- วัดก่อนใช้ AI, ระหว่างทำ, และหลังใช้ AI ด้วยหลักฐานที่ตรวจสอบได้
- ใช้คำถามอธิบายเหตุผล การสาธิต การลงมือทำ และการสะท้อนคิด
- ไม่ใช้ AI detector เป็นหลักฐานเดี่ยวในการกล่าวหานักเรียน
- ไม่ส่งชื่อ ภาพใบหน้า ข้อมูลสุขภาพ คะแนนหรือข้อมูลระบุตัวเด็กเข้าสู่ AI สาธารณะ
- ตรวจความถูกต้อง อคติ และแหล่งข้อมูลทุกครั้ง

## 5. การเชื่อมระบบที่มีอยู่
WD Growth: ใช้แนวคิดวัดทักษะและความก้าวหน้ารายบุคคล โดยไม่เพิ่มการเชื่อม API หรือคัดลอกข้อมูลจริงใน M0
PLC: ใช้แผนทดลองสอน บันทึกสิ่งที่สังเกต และปรับกิจกรรมตามหลักฐาน ไม่อ้างว่าเชื่อมระบบอัตโนมัติแล้ว

## 6. Work packages
- **M0** สำรวจ repo, สร้างแผนแม่บท, โครงอบรม, เกณฑ์ตรวจรับ (PR เอกสารเท่านั้น)
- **M1** เขียนบท 1–8 พร้อมตรวจข้อเท็จจริงและเอกสารอ้างอิง
- **M2** จัดทำตัวอย่างใบงาน 2 แบบ, แบบบันทึกวิธีคิด, รูบริก, ข้อตกลงใช้ AI, PLC reflection
- **M3** คู่มือวิทยากร/สไลด์/กิจกรรมฝึกปฏิบัติและทดสอบกับครู
- **M4** แปลงเนื้อหาที่ตรวจรับแล้วเป็น e-book; เพิ่มทะเบียนใน assets/manuals-data.js ด้วย PR แยก
- **M5** ทดลองในชั้นเรียน, ประเมินผล, สะท้อน PLC, ปรับรุ่นคู่มือ

## 7. Acceptance gates
G0: เอกสาร M0 ครบ ลิงก์ถูก ไม่มีข้อมูลส่วนบุคคล ไม่มีการเปลี่ยนเว็บ
G1: เนื้อหาแต่ละบทถูกต้องตามวัย มีตัวอย่างและแหล่งอ้างอิง
G2: ทดลองใบงานและรูบริกโดยครูจริง ตรวจว่าประเมินวิธีคิดได้
G3: ผู้รับผิดชอบอนุมัติฉบับสาธารณะก่อนเพิ่มเข้า e-book
G4: ทดสอบ Local-First บน Windows, iPhone/iPad, accessibility และ PWA ก่อนเผยแพร่
G5: เก็บผล PLC โดยใช้ข้อมูลไม่ระบุตัวบุคคลและทบทวนคู่มือ

## 8. Governance
- ไม่แก้เว็บไซต์, ระบบล็อกอิน, PWA, ฐานข้อมูล หรือระบบ WD Growth/PLC ใน M0
- Repository manual เป็นพื้นที่สาธารณะ; แผนภายในและข้อมูลนักเรียนจริงต้องอยู่แหล่งที่จำกัดสิทธิ์
- ไม่เพิ่ม GitHub Actions; ทดสอบ Local-First
- การ Merge PR เอกสารไม่เท่ากับอนุมัติเผยแพร่ e-book
- ก่อนเขียนบทเชิงนโยบายให้ตรวจแหล่งอ้างอิงล่าสุดและข้อกำหนดสถานศึกษา
