# กติกาคลังคู่มือสาธารณะโรงเรียนบ้านวังด้ง (2569)

**สถานะ:** ร่างสำหรับผู้บริหาร/ฝ่ายวิชาการ/ผู้ดูแลข้อมูลตรวจรับก่อนเปิดเว็บจริง

## 1. เขตข้อมูลที่อนุญาตให้เผยแพร่

| กลุ่ม | บน GitHub Pages Public | ตัวอย่าง |
|---|---|---|
| A — สาธารณะ ผ่านตรวจรับ | เผยแพร่ได้ | คู่มือขั้นตอนทั่วไป/ภาพหน้าจอสังเคราะห์/นโยบายที่อนุมัติ |
| B — บุคลากรภายใน | ห้ามเผยแพร่ใน public repo | แบบฟอร์มมีข้อมูลเด็กจริง แนวทางภายในที่จำกัดสิทธิ์ |
| C — ข้อมูลส่วนบุคคล/ความปลอดภัย | ห้ามเด็ดขาด | ชื่อและคะแนนรายบุคคล, รูปเด็ก, PIN/password/token, API secrets, DB dump, URL ข้อมูลลับ, เฉลยจำกัดสิทธิ์ |

**ข้อควรจำ:** การสร้าง PR ใน repository Public ก็ถือว่าเปิดเผยเนื้อหาแล้ว (แม้เป็น Draft) ดังนั้นต้องคัดกรองก่อน Commit/PR ไม่ใช่รอถึง Merge หรือเปิด Pages

## 2. งาน WD Growth — ต้นทางกับคู่มือเผยแพร่

- ต้นทางปัจจุบัน: repository ระบบการเรียนรู้ภายในที่จำกัดสิทธิ์; คู่มือครูอยู่ระหว่างตรวจรับ ณ 23 ต.ค. 2569
- **ไม่คัดลอกเนื้อหาคู่มือฉบับร่างจาก repo Private มาใน repo Public โดยอัตโนมัติ** รวมถึงข้อมูลภายใน ตัวอย่างเด็กจริง ภาพหรือบันทึกผู้เรียน
- เมื่อผู้รับผิดชอบตรวจรับ ให้สร้าง **Public Edition** โดยทบทวนภาษา รูป แบบฟอร์ม อ้างอิง/เวอร์ชันและภาพตัวอย่างจากข้อมูลสมมติ
- เจ้าของโครงการอนุญาตให้เผยแพร่ **ฉบับเรียบเรียงใหม่สำหรับสาธารณะ** ของคู่มือบันทึกการพัฒนารายบุคคลลง e-book ในวันที่ 23 ต.ค. 2569 โดยไม่มีข้อมูลเด็กจริง ตัวอย่างทั้งหมดสมมติ และไม่เปิดเผยเนื้อหาไฟล์ภายในโดยตรง; เอกสารฉบับร่างใน repo ต้นทางยังไม่ถูก Merge
- แยกสถานะวิชาการ (Approved Content) จากสถานะ Pages Deployment (Deployed); ไม่มีสถานะใดแทนกัน

## 3. วงจรรับรองคู่มือ

1. ผู้จัดทำที่ repo ต้นทางเสนอฉบับแก้ไข พร้อมวัน/เวอร์ชัน/เจ้าของข้อมูล
2. เจ้าของกระบวนงานหรือฝ่ายวิชาการตรวจความถูกต้องและสอดคล้องระบบ ณ เวลานั้น
3. ผู้ดูแลข้อมูลตรวจว่าเป็นหมวด A และไม่มีข้อมูลผู้เรียน/บุคลากรที่ระบุตัวได้หรือข้อความความลับ
4. จัดทำเนื้อหาอ่านง่ายเป็นชุดหน้า e-book และทดลองใช้งานบนโทรศัพท์/คอมพิวเตอร์ด้วยตัวอย่างสมมติ
5. เปิด PR ใน `infobwd/manual` เพื่อให้เจ้าของคู่มือและผู้บริหารตรวจรับ; เมื่ออนุมัติแล้วจึง Merge และเปิดหน้า Public
6. ระบุวันที่ปรับปรุงครั้งล่าสุดและเก็บประวัติการเปลี่ยนแปลง; เมื่อวิธีปฏิบัติในระบบจริงเปลี่ยน ให้เริ่มทบทวนคู่มือ

## 4. แนวการจัดหมวดหมู่

- เริ่มต้นใช้งาน (`getting-started`)

หนึ่งเล่มมีหมวดหลักหนึ่งรายการและแท็กหลายคำได้; หลีกเลี่ยงรายการซ้ำเพื่อให้ค้นหาได้ง่าย

## 5. กติกาสำหรับผู้พัฒนา

- Local-First: HTML/CSS/JS แบบ static ไม่มี build step, ไม่ดึง dependencies จาก CDN จำเป็น, ไม่พึ่งฐานข้อมูลหรือ API ผู้เรียน
- GitHub Pages: เลือก Deploy from a branch / main / root หลังผ่าน Acceptance; **ไม่เพิ่ม GitHub Actions workflow** เป็นส่วนหนึ่งของโครงการ
- ห้ามอ้างว่าทดสอบ Windows, PWA, การพิมพ์จริง หรือการแสดงผล Pages ผ่านแล้วหากยังไม่มีหลักฐาน
- รองรับ Accessibility: คีย์บอร์ด, contrast, เลขหน้า/สารบัญ, responsive, reduced-motion, ไม่ทำให้การอ่านต้องใช้ animation
- ตรวจว่าเว็บไซต์ไม่ index เนื้อหาที่ยังไม่ได้อนุมัติ: รายการสถานะ draft/planned แสดงชื่อ/ข้อมูลกำกับที่ปลอดภัยเท่านั้น และไม่มีเนื้อหาคู่มือ
- ห้ามสร้างปุ่ม login หรือซ่อนเนื้อหาไว้ใน client JS เพื่ออ้างว่าเข้าถึงได้เฉพาะผู้ได้รับสิทธิ์ (source Public)
- ก่อนเปิด Custom Domain ต้องตรวจความเป็นเจ้าของ DNS/SSL และนโยบายเว็บไซต์; ยังไม่มีโดเมนที่ได้รับอนุมัติสำหรับโครงการนี้

## 6. Acceptance ของต้นแบบ

- [ ] หน้าแรกเปิดได้ที่ localhost โดยไม่ต้อง login หรือ npm
- [ ] ค้นหาจากชื่อ/แท็ก/หมวดและเปลี่ยนหมวดแล้วรายการตรงกัน
- [ ] สาธิต reader เปิดได้ 8 หน้า: desktop 2 หน้า/ครั้ง, mobile 1 หน้า/ครั้ง
- [ ] สารบัญ แป้นลูกศร ปุ่มปิด หน้าก่อน/ถัดไป ใช้งานจริง
- [ ] เพิ่ม/ลดตัวอักษรได้โดยไม่มีข้อความหาย; มือถือเลื่อนอ่านภายในหน้าได้
- [ ] เล่ม “รอตรวจรับ” และ “ตามแผน” ไม่มีปุ่มเปิดอ่านและไม่มีข้อมูลลับ
- [ ] ไม่มี JavaScript console errors, ปุ่มใช้คีย์บอร์ดได้, ตรวจ Reduced Motion
- [ ] เจ้าของโครงการตรวจแบบและการจัดหมวดพร้อมอนุญาต Merge/เปิด Pages แยกต่างหาก

## 7. งานถัดไป

หลังต้นแบบผ่าน QA: ตั้งค่าหน้า Pages, ทดลองจริงบน iPhone/iPad/Android/desktop แล้วจึงคัดเลือกคู่มือฉบับแรกที่ผ่านวิชาการ/ข้อมูลเพื่อแปลงเป็น e-book. หากในอนาคตต้องการคู่มือเฉพาะครูที่มีข้อมูลภายใน ต้องแยกไป host ที่มี Backend Authentication/Authorization และไม่ใช้ Pages เป็นตัวป้องกันข้อมูล

## 28 ต.ค. 2569 — ข้อยกเว้นที่อนุญาตเฉพาะสารสนเทศภาพรวม WD Growth A1.0

ผู้บริหารโรงเรียนอนุญาตให้ **คู่มือ WD Books ฉบับ Public** แสดง **ค่าเฉลี่ยระดับชั้น × รายวิชาเท่านั้น** ของ Baseline A1.0 ปีการศึกษา 2569 (ป.1–ป.4) เพื่อให้ครูและผู้สนใจใช้เป็นประเด็นเตรียม PLC โดยมีเงื่อนไขทั้งหมดต่อไปนี้:

- ต้องมีข้อความ **“ข้อมูลเบื้องต้น · ยังไม่ผ่านครูตรวจรับ · ไม่ใช่ผลทางการ”** ชัดเจน และบอกว่าเป็นค่าเฉลี่ยจากแบบที่ได้รับ (ไม่ได้ยืนยันว่าครบตามทะเบียน)
- อนุญาต 4 ชั้น (ป.1–ป.4) และ 3 รายวิชาเฉพาะค่าเฉลี่ย **เต็ม 10** ไม่แสดงเลขที่, ตัวระบุนักเรียน, คะแนนรายข้อ, การกระจายหรือกลุ่มย่อย, ชิ้นงาน, ภาพประเมิน, ต้นฉบับ/JSON รายคน
- ห้ามเชื่อม Public JS ไปยังฐานข้อมูลหรือ API ภายใน และห้ามใช้คะแนนประเมินครู/จัดอันดับชั้นเรียน
- หากพบข้อผิดพลาดหลังครูตรวจรับ ให้ออกหนังสือเวอร์ชันใหม่พร้อมวันที่/ร่องรอยแก้ไข และป้ายสถานะที่เหมาะสม **ไม่แก้ข้อมูลต้นทางใน Private Git เงียบ ๆ**
- การอนุญาตนี้ **ไม่ครอบคลุมการเผยแพร่คะแนนตามเลขที่** บน GitHub Pages และไม่อนุญาตให้ปิดบังคะแนนรายคนด้วย PIN ฝั่ง JavaScript
- ค่าคะแนนอยู่ในเล่ม `assets/wd-growth-plc-information-guide.js` Public Edition 1.1 และต้องผ่านการตรวจให้แน่ใจว่าไม่มีข้อมูลรายบุคคลหรือบทสรุปชวนตีตราเด็ก

ข้อยกเว้นนี้ใช้กับ **ผลรวมระดับชั้นที่ได้รับอนุญาต** เท่านั้น; มาตรฐานการคุ้มครองข้อมูลกลุ่ม B/C เดิมยังคงบังคับใช้กับข้อมูลส่วนอื่นทั้งหมด.
