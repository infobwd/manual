# WD Books — แผนบูรณาการ WD Growth / PLC / ID Plan / PA / ประกันคุณภาพ / เชี่ยวชาญ

สถานะ: **ANALYSIS + IMPLEMENTATION PLAN**; ไม่ใช่การรับรองผลการปฏิบัติงานหรือคุณสมบัติวิทยฐานะ

## ตรวจเอกสารจริงใน repo `infobwd/wd-standard`
- `docs/WD_GROWTH_MASTER_PLAN.md`: หลักประเมินเพื่อพัฒนา, ครูบันทึก Baseline/แผนรายทักษะ/Retest, ผู้ปกครองร่วม, ผู้บริหารทบทวนรายสัปดาห์, PLC 7 สัปดาห์; ตัวชี้วัดเป็น **proposed pilot**, ไม่ใช่ผลจริงที่รับรอง
- `docs/WD_GROWTH_ASSESSMENT_DESIGN.md`: แยก baseline/practice/formative/retest, เครื่องมือเทียบเคียง, ปฐมวัย 4 ด้าน, ไม่จัดอันดับเด็ก
- `docs/WD_GROWTH_CURRENT_EXECUTION_STATUS.md`: ระบุข้อจำกัดการทดสอบ/ขึ้น Host; ห้ามสรุปว่าใช้งาน Production ครบถ้วนจากแผน
- ยังไม่ได้ตรวจแฟ้มบันทึก PLC 7 สัปดาห์ฉบับปฏิบัติจริงและผลการนิเทศทั้งหมด; ต้องขอรับรองสถานะจากครูและผู้บริหาร

## One improvement loop
Baseline → ครูยืนยันข้อมูล → แผนพัฒนาผู้เรียนรายคน/รายทักษะ → ครูพัฒนาวิธีสอนตาม ID Plan → PLC 7 สัปดาห์ → ทดลองและติดตาม → Retest → Mentor/นิเทศ → ปรับแผน.

## แผนคู่มือครู
เพิ่มบทแยกใน PR ใหม่ (เพราะ PR #71 merge แล้ว): วิธีใช้ผล Baseline วางแผนรายคน, ครูร่วมรับผิดชอบคนเดียวกัน, ตัวอย่าง PLC 7 สัปดาห์, เชื่อม ID Plan/PA, หลักฐานกระดาษ+ระบบ, ความปลอดภัยข้อมูล. ต้องตรวจตัวอย่างจากข้อมูลจริงที่อนุญาตก่อนเผยแพร่.

## แผนคู่มือผู้บริหาร
เพิ่ม 3 หน้าใน PR #72: วงจร WD Growth, ตัวอย่างโครง PLC 7 สัปดาห์, แผนผังหลักฐาน 3 เป้าหมาย. โครงสัปดาห์เป็น **ข้อเสนอ** จนตรวจปฏิทิน PLC ฉบับจริง.

## Evidence register ขั้นต่ำ
| รายการ | เจ้าของ | หลักฐานต้นทาง | ตรวจรับ |
|---|---|---|---|
| Baseline | ครู | ผลรายทักษะ/เครื่องมือ version | ครูยืนยัน |
| แผนผู้เรียนรายบุคคล | ครูประจำชั้น/วิชา | แผน+เป้าหมาย+วันที่ | ผู้รับผิดชอบยืนยัน |
| PLC | หัวหน้า PLC | วาระ/บันทึก/การปรับกิจกรรม | คณะ PLC ยืนยัน |
| Mentor/นิเทศ | ผอ. | บันทึกคำปรึกษา/ข้อเสนอแนะ | ผอ. ยืนยัน |
| Retest | ครู | เครื่องมือเทียบเคียงและผล | ครูยืนยัน |
| ID Plan/PA | ครู+ผอ. | แบบตามต้นสังกัด | ตรวจเกณฑ์เฉพาะ |
| ประกันคุณภาพภายนอก | งานประกัน | SAR/ผลระบบ/การมีส่วนร่วม | map เกณฑ์รอบประเมิน |
| วิทยฐานะเชี่ยวชาญ | ผู้บริหาร | หลักฐานบทบาทผู้นำและผลเชิงระบบ | ตรวจเกณฑ์ ก.ค.ศ. เฉพาะตำแหน่ง |

## Gates ก่อนกล่าวอ้าง
1. ยืนยันข้อมูลจากระบบ Production หรือแฟ้มกระดาษจริงและช่วงเวลา
2. แยกแผน/ดำเนินการ/ผลยืนยัน; ห้ามสร้างตัวเลขหรือหลักฐานย้อนหลัง
3. ตรวจเกณฑ์ สมศ. รอบประเมินและ ก.ค.ศ. สำหรับผู้บริหารเชี่ยวชาญล่าสุดฉบับเต็ม
4. จัดเก็บหลักฐานบุคคลในพื้นที่ควบคุมสิทธิ์ ไม่ใส่ใน GitHub Public/WD Books
5. ตรวจเนื้อหาคู่มือกับครูและผู้บริหารก่อน Merge/เผยแพร่
